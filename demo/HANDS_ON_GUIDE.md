# InfraRed 핸즈온 — 학생·교수가 직접 공격해보기

> 발표자 주도 데모(`DEMO_RUNBOOK.md`) 다음에, 청중이 **직접 공격을 날려보고
> InfraRed가 잡아내는 걸 체험**하는 참여형 세션. "내가 공격했더니 시스템이 막았다"는
> 경험이 가장 기억에 남는다.

## 사전 준비 (발표자, 1회)

1. 데모 머신에서 로컬 스택 기동: `./run-local.sh`  → 대시보드 http://localhost:3000
2. 대시보드를 빔프로젝터/큰 화면에 로그인해 띄워둠 (`admin@infrared.local` / `infrared123`)
3. 참가자가 쓸 터미널 1대 준비 (데모 머신이거나 같은 네트워크 머신)

---

## 모드 1 — 무설정 셀프 공격 런처 (전원 추천)

가장 안전하고 회전이 빠르다. 참가자는 설정 없이 명령 하나만 실행하면 메뉴가 뜬다.

```bash
cd demo
python3 try_attack.py
```

진행:
1. 참가자가 메뉴에서 공격을 고른다 (1~6번: 브루트포스 / 계정탈취+지속성 / 웹쉘 / 권한상승 / 랜섬웨어 / 측면이동)
2. 스크립트가 실제 파이프라인(`debug/replay-events`)으로 공격 이벤트를 주입
3. **큰 화면의 대시보드**에 시그널·인시던트가 실시간으로 뜬다
4. 참가자가 인시던트를 클릭해 타임라인·MITRE 매핑·자동대응을 직접 확인

장점: SSH·hydra 지식 불필요, 실패율 0, 한 명당 ~30초라 많은 사람이 돌아가며 체험 가능.

> 진행 팁: 참가자에게 **"고르기 전에 이 공격이 뭘 할지 예상해보라"** 고 한 뒤,
> 대시보드에 뜬 결과와 맞춰보게 하면 학습 효과가 크다.

---

## 모드 2 — "공격자 자리" (실제 공격, 도전적인 참가자용)

진짜 다른 머신에서 실 공격을 날리고 싶은 참가자용. (2-VM 구성 필요, `DEMO_RUNBOOK.md` 참고)

```bash
./attack.sh <타깃IP>        # 막마다 Enter로 진행
# 또는 한 단계만:
./attack.sh <타깃IP> 1      # 브루트포스만
```

학생 한 명을 공격자 VM에 앉히고 단계별로 직접 치게 한다. 마지막 6막에서
**자기가 공격하던 세션이 자동 차단으로 끊기는 걸** 본인이 체험하는 게 하이라이트.

---

## 모드 3 — 탐지 회피 챌린지 (심화, 토론용)

"InfraRed에 안 걸리고 악성 행위를 해보라"는 도전. 행위 기반 탐지가 왜 우회하기 어려운지를 몸으로 배운다.

진행:
1. 참가자에게 타깃 셸 접근을 준다 (모드 2의 SSH 세션)
2. 미션: **경보 없이** 다음 중 하나를 시도 — 백도어 심기 / 민감파일 읽기 / 파일 대량 변경
3. 대부분 즉시 걸린다. 왜 걸렸는지 대시보드로 함께 분석:
   - `authorized_keys`·`cron` 수정 → 해시/무결성 감시에 무조건 걸림
   - `/etc/passwd`,`/etc/shadow` 접근 → 민감경로 감시
   - `/tmp` 실행, 대량 파일 변경 → 행위 패턴 탐지
4. 토론: "시그니처 백신이라면 이 중 무엇을 놓쳤을까?" → InfraRed의 차별점으로 연결

> 이 모드는 "정답은 거의 못 빠져나간다"가 포인트다. 빠져나가는 시도가 나오면
> 그 자체로 훌륭한 탐지 개선 토론 소재가 된다.

---

## 리셋 & 운영

- 참가자 사이 초기화는 보통 불필요(인시던트가 누적되며 쌓일 뿐). 깔끔히 비우려면:
  `./run-local.sh reset && ./run-local.sh` (볼륨 초기화 후 재기동)
- 모드 2를 썼다면 타깃 VM에서 `sudo ./target_setup.sh reset`
- 대시보드 인시던트가 너무 많이 쌓이면 새로고침으로 최신만 보면 됨

## 진행 타이밍(예시, 15분)

1. (3분) 발표자 주도 풀 데모 1회 — 흐름 보여주기
2. (8분) 모드 1 셀프 런처 — 참가자 4~6명 돌아가며
3. (3분) 모드 3 회피 챌린지 1명 + 전체 토론
4. (1분) MTTD/MTTR 지표로 마무리
