# InfraRed 라이브 공격 데모 — 진행 대본 (Run-of-Show)

> 대상 청중: 교수·학생 / 형식: 2대 머신 라이브 공격 시연 (약 10분)
> 핵심 메시지: **"백신(시그니처)이 못 잡는 '정상 도구를 악용한 침투'를, InfraRed는 행위·체인·AI로 잡아내고 자동 차단한다."**

---

## 0. 한 줄 컨셉

안랩 V3 같은 백신은 *알려진 악성코드 파일*을 잡는다. 하지만 실제 침해는 SSH·cron·systemd 같은 **정상 도구를 악용**해 들어온다. 이 데모는 **다른 컴퓨터(공격자 VM)** 에서 진짜 공격을 쏘고, InfraRed가 탐지 → 상관분석 → AI 분석 → **자동 차단**까지 하는 전 과정을 라이브로 보여준다. 마지막엔 공격자 머신이 실제로 접속을 잃는다.

---

## 1. 환경 구성 (권장: 노트북 1대 + VM 2개)

| 역할 | 머신 | 구성 |
|------|------|------|
| **타깃(피해자)** | VM A (Ubuntu 22.04) | InfraRed 백엔드+대시보드+에이전트, sshd, 미끼·폐기 데이터 |
| **공격자** | VM B (Kali 또는 Ubuntu) | `hydra`, `sshpass`, `attack.sh` |
| 네트워크 | host-only / internal | 두 VM이 서로 보이되 외부망과 격리 |

> 왜 이 구성인가: 출처 IP가 다른 별도 머신으로 잡혀 "짜고 친 티"가 안 나면서도, **스냅샷으로 매 리허설을 초기화**할 수 있어 라이브 실패율이 가장 낮다. 공격자 VM 창을 **별도 모니터/화면**에 띄우면 "다른 컴퓨터에서 공격" 연출이 그대로 산다.

### 사전 준비 (1회)
1. 타깃 VM에서: `sudo ./target_setup.sh`  → IP·계정·대시보드 주소가 출력됨
2. 공격자 VM에서: `sudo apt install -y hydra sshpass`
3. **두 VM 모두 스냅샷 저장** (리허설/실전 사이 초기화용)
4. 리허설 1~2회 → 타이밍 체감, 자동 차단까지 걸리는 초 확인

### 화면 배치
- **좌/메인 화면**: InfraRed 대시보드 (`http://<타깃IP>:3000`, admin@infrared.local / infrared123)
- **우/보조 화면**: 공격자 VM 터미널 (`attack.sh` 실행)

## 2. 막별 진행 대본

각 단계는 공격자 VM에서 `./attack.sh <타깃IP>` 실행 시 **Enter로 한 막씩** 진행된다. 멘트는 대시보드를 가리키며.

### 🎬 오프닝 (30초)
> "지금 보시는 왼쪽은 보안관제 대시보드, 오른쪽은 **완전히 다른 컴퓨터** — 공격자의 노트북입니다. 제가 지금부터 저 공격자 머신에서 이 서버를 실제로 해킹하겠습니다. 백신은 이런 공격을 못 봅니다. InfraRed가 어떻게 반응하는지 보시죠."

### 1막 — 브루트포스 (T1110)
- 실행: `attack.sh` 1단계 (hydra)
- 화면: 대시보드에 **AUTH-001(브루트포스)** → **AUTH-004(실패 후 성공)** 시그널
- 멘트: *"수십 번 로그인 실패 끝에 비밀번호를 뚫었습니다. 출처 IP를 보세요 — 저 공격자 머신의 실제 IP입니다. 여기까진 아직 '의심' 단계예요."*

### 2막 — 침투 (T1078)
- 화면: 정상 로그인으로 보이는 세션. 단독으로는 경보가 약함
- 멘트: *"방화벽도 백신도 이건 그냥 정상 SSH 로그인으로 봅니다. 문제는 그 다음이죠."*

### 3막 — 지속성 (T1098 / T1053) ★ 첫 와우
- 공격: `/root/.ssh/authorized_keys` 백도어 키 + `/etc/cron.d` 백도어
- 화면: **PERSIST-001 / PERSIST-002** 발화 → **attack_chain 엔진이 1~3막을 묶어 `SSH_ACCOUNT_COMPROMISE_WITH_PERSISTENCE` 를 CRITICAL로 자동 승격** (confidence +0.35)
- 멘트: *"여기가 핵심입니다. 개별 알림 5개가 아니라, 시스템이 점들을 스스로 연결해 **하나의 명명된 공격 시나리오**로 끌어올렸습니다. 이게 백신과의 결정적 차이입니다."*

### 4막 — 미끼 작동 (T1552) ★ 정밀도 포인트
- 공격: 민감 파일 열람 + **미끼 AWS 자격증명** 접근
- 화면: Deception 경보
- 멘트: *"우리가 미리 심어둔 가짜 자격증명입니다. 정상 사용자는 절대 안 건드리죠. 공격자가 밟는 순간 **오탐 거의 0의 확정 신호**가 됩니다."*

### 5막 — 랜섬웨어 (T1486) ★ 클라이맥스
- 공격: `/tmp` 페이로드 실행(EXEC-001) + 문서 150개 `.locked` 대량 변조(EXEC-003) + 랜섬노트
- 화면 동시 2가지:
  - **AI 인시던트 리포트**: `Analyze` 클릭 → Bedrock이 전체 킬체인을 사람 언어로 요약 + 권장 조치
  - **자동 대응**: `iptables` 자동 차단 + SSH 키 **JIT 회수** + 포렌식 수집 트리거
- 멘트: *"단순 룰 엔진이 아니라 AI가 사건 전체를 서술하고, 동시에 시스템이 스스로 대응을 실행합니다."*

### 6막 — 차단 증명 (Containment) ★ 마무리 한 방
- 공격: 공격자가 다시 명령 시도 → **접속 거부**
- 멘트: *"공격자가 다시 들어오려 합니다… 보세요, 끊겼습니다. InfraRed가 저 머신을 네트워크에서 격리했습니다."*
- 마무리: KPI 페이지에서 **MTTD / MTTR (탐지 X초, 대응 Y초)** 숫자로 정량 마감

| 막 | 공격 행위 | 탐지 룰 | MITRE | 에이전트 감시 지점 |
|----|-----------|---------|-------|--------------------|
| 1 | SSH 브루트포스 | AUTH-001/003 | T1110.001 | auth.log tail |

| 1~3 | 체인 상관분석 | AttackChainMatcher | — | 백엔드 correlation |

## 4. 리셋 & 재실행

```bash
# 타깃 VM
sudo ./target_setup.sh reset      # 흔적 제거 + .locked 원복 + iptables 초기화
# 또는 VM 스냅샷 복원 (가장 깔끔)
```
공격자 VM은 상태가 없으므로 `attack.sh` 재실행만 하면 됨.

## 5. 실패 대비책 (Contingency)

| 위험 | 대비 |
|------|------|
| 라이브에서 무엇이든 안 터짐 | **동일 시연을 미리 녹화**해 백업 영상 준비 (1순위 안전장치) |
| hydra가 비번 못 찾음 | 워드리스트에 정답이 8번째로 심겨 있음. 타깃 `sshd`·계정·`MaxAuthTries` 확인 |
| 자동 차단이 느림 | 6막 전에 "정책 평가에 수 초" 멘트로 자연스럽게 텀, `attack.sh 6` 재실행 |
| 네트워크 꼬임 | host-only 어댑터 고정 IP 권장. 물리 2대 대신 VM 2개를 쓰는 이유 |
| 백엔드 미기동 | 데모 5분 전 `http://<IP>:3000` + `:8000/healthz` 헬스체크 |
| 청중 참여 | 학생 1명에게 `attack.sh 1` 직접 타이핑하게 하면 몰입↑ |

## 6. 대안 모드 (참고)

- **완전 결정적 모드**: 실제 공격 대신 `POST /api/v1/debug/replay-events`로 BAS 픽스처(`backend/tests/detection/fixtures/scenarios/*.jsonl`)를 재생 → 실패율 0이지만 "라이브 공격" 연출은 약함. 리허설/백업 영상 제작에 활용.
- **풀 클라우드 모드**: 타깃을 AWS(기존 terraform)에 두고 공격은 내 노트북에서 → 출처가 진짜 공인 IP. 인터넷 의존성 때문에 실전 라이브엔 비권장, 사전 녹화에 적합.
